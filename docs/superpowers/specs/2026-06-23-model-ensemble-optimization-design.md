# BDC2026 多模型集成优化设计

日期：2026-06-23

## 摘要

当前本地分数为 `0.083800513818`，本轮的实际目标是在保持以下约束不变的前提下，尽量把分数推进到 `0.10+`：

- 全程离线可复现
- Docker 可提交
- `output/result.csv` 输出格式合规
- 现有 `train -> test -> score` 链路继续稳定可用

当前方案已经明显优于 baseline，工程链路也已经跑通。因此下一阶段不应再做“碰运气式”提分，而要做更贴近实际落地的稳健优化。本设计聚焦三件事：

- 增强模型多样性
- 用验证结果驱动集成选择
- 做少量但贴近 Top5 目标的训练优化

## 选定方案

本轮采用三层优化路径：

1. 先补一个轻量级 walk-forward 时序验证层，避免模型选择只看单次时间切分
2. 再把当前固定的双模型平均，升级成验证驱动的多模型集成
3. 最后只做少量目标导向优化，而且必须建立在验证层已经稳定的前提下

选择这条路径的原因是：它在提分空间、可复现性和实际落地之间最平衡。它既能继续冲击 `0.10+`，也能降低对当前 `data/test.csv` 单一窗口过拟合的风险，同时不会把 Docker 和推理接口复杂化。

## 非目标

本阶段不做以下事项：

- 不引入神经网络或预训练模型
- 不引入任何联网依赖
- 不修改提交结果格式
- 不做大规模特征系统重写
- 在模型方案稳定前，不调整 Docker 打包逻辑

## 为什么选这条路

### 方案 A：只保留 XGB/LGB，继续调参

优点：

- 工程成本最低
- 复现风险最低

缺点：

- 分数上限可能有限
- 无法解决当前固定 `1:1` 集成过于僵硬的问题
- 仍然过度依赖单次验证切分，容易被噪声误导

### 方案 B：推荐方案，做验证驱动的多模型集成

优点：

- 直接符合你希望优先走“多模型方向”的目标
- 不改变最终提交接口，但能显著增强模型多样性
- 后续每次优化都可以复用这套实验判别框架

缺点：

- 训练编排和元数据会比现在稍复杂
- 需要认真处理集成权重和失败回退逻辑

### 方案 C：先大改标签或目标函数

优点：

- 理论上上限可能更高

缺点：

- 风险更高
- 如果验证层不稳，很难判断改动是真的有效还是偶然涨分
- 更容易被本地 score 误导

综合来看，方案 B 最适合当前阶段。因为现在不是“从零做能跑方案”，而是“在已有强方案上稳健冲分”。

## 范围

### Phase 1 包含

- 多折时序验证工具
- 除固定 z-score 平均外的其他集成方式
- 1 个与 XGBoost / LightGBM 风格差异明显的新模型
- 保证训练和推理可复现的元数据扩展
- 能支持模型比较的实验报告输出

### Phase 1 不包含

- 大规模新特征扩展
- 广义超参数搜索系统
- Docker 镜像重构
- 自动化打包链路改造

## 整体架构

主流程仍然保持 `train -> test -> score`，但训练阶段会更结构化。

### 训练流程

1. 读取并标准化 `data/train.csv`
2. 生成当前特征集
3. 构建排序标签和可训练样本
4. 在多个 walk-forward 时序折上评估候选模型
5. 统计每个模型及每种集成方式的验证指标
6. 选择最优的生产集成策略
7. 按当前生产约定，在完整训练区间上重训入选模型
8. 保存模型文件和集成元数据

### 推理流程

1. 读取模型元数据和最终选定的集成策略
2. 基于 `data/train.csv` 重建特征
3. 对每只股票仅保留最新一行
4. 运行所有入选子模型
5. 应用保存下来的集成策略
6. 输出相同格式的合规 `output/result.csv`

## 模型规划

### 保留的现有模型

- `XGBoost Ranker`
- `LightGBM Ranker`

### 新增模型候选

本阶段先只加 1 个辅助模型，要求与当前两类排序树模型的归纳偏置有明显区别，同时仍然适合离线复现。

优先候选为：

- `HistGradientBoostingRegressor`

训练目标为连续 `future_return` 回归。

选择它的原因：

- 它提供的是回归风格信号，而不是再增加一个类似的排序目标
- 它属于当前 Python 科学计算栈内可直接使用的模型
- 可复现性较好，适合离线环境
- 它的价值更可能来自“分数形状差异”，而不仅是单模型强度

如果这个模型效果不理想，备用候选为：

- `ExtraTreesRegressor`

本阶段只引入 1 个新模型家族，避免范围过大、调试困难。

## 集成设计

当前固定的 `z-score` 等权平均，将升级为可配置集成策略。

### 待评估的集成候选

- `zscore_average_equal`
- `rank_average_equal`
- `validation_weighted_zscore_average`

### 权重选择原则

集成权重基于 walk-forward 多折验证结果计算，默认规则如下：

- 负贡献裁剪为 0
- 正贡献归一化到总和为 1
- 如果所有模型都很弱或权重无效，则回退到等权

这样做可以保持推理阶段足够简单，同时让集成真正反映历史验证中的有效性。

## 验证设计

当前“单次后 20% 时间切分”不再作为唯一主判据，而是改成轻量级 walk-forward 方案。

### 折设计

- 严格保持时间顺序
- 使用样本尾部的多个连续验证窗口
- 每个 fold 都要求足够长的训练历史

首版建议：

- 使用 3 个 walk-forward folds
- 每个 fold 的验证集都是连续交易日区间
- 训练区间按时间向前扩展，而不是打乱重采样

### 主指标

继续使用当前的 top-`k` relative score，因为它与比赛目标和现有评估口径最一致。

### 次级诊断信息

- 各模型在不同 fold 上的稳定性
- 集成相对最佳单模型的增益
- Top5 选股重叠率与差异性

验证层的目标不是“精确预测未来正式得分”，而是减少我们在模型选择时被假阳性误导。

## 目标优化

在验证层稳定后，本阶段允许加入 1 个有限的目标导向增强。

### 推荐增强

为新增的回归模型增加一条连续收益辅助目标路径：

- XGB / LGB 仍然保持当前十分位排序标签
- 新增辅助模型预测裁剪后的连续 `future_return`
- 最终集成同时融合排序风格分数和回归风格分数

这样做比直接替换现有排序标签更安全。它能在保留当前主方案稳定性的前提下，增加额外信号来源。

### 延后优化

如果 Phase 1 跑稳后仍未达到目标，下一轮再考虑：

- 头部样本加权
- 替代性标签分桶方式
- 树模型的混合 rank/regression 训练

这些改动都先延后，因为它们的回撤风险更高。

## 数据与元数据变更

训练产物需要新增记录以下信息：

- 最终入选的子模型列表
- 最终采用的集成方式
- 基于验证得到的模型权重
- fold 配置
- 每折指标和聚合指标
- 是否触发过等权回退

这样可以保证 `test.py` 的推理逻辑仍然是确定性的、自包含的。

## 异常处理

更新后的训练和推理链路需要在以下情况中安全失败：

- 某个候选模型在某一折训练失败
- 某个 fold 的有效 ranking groups 不足
- 某个模型输出常数分数，导致标准化失败
- 验证权重结果无效
- 推理时元数据声明的模型文件缺失

要求行为如下：

- 明确打印失败原因
- 尽量只排除失败模型，而不是整条链路直接崩掉
- 如果还有有效子模型，则回退到更小的有效集成
- 只有最终推理链路有效时才允许输出 `result.csv`

## 测试策略

### 功能检查

- 现有 `train -> test -> score` 仍能完整跑通
- `output/result.csv` 继续合规
- 推理逻辑能正确读取新的集成元数据

### 模型选择检查

- walk-forward 报告能正常输出且可读
- 最优集成选择过程可以追溯
- 等权回退逻辑可以被覆盖到

### 回归检查

- 当前双模型路径仍然可以作为 fallback 保留
- 当第三模型关闭时，输出行为与当前逻辑兼容

## 成功标准

本阶段满足以下条件则视为成功：

- 本地分数实质性接近或达到 `0.10`
- walk-forward 验证中，最终选定集成在聚合表现上不弱于当前固定集成
- 训练与推理仍然离线可复现
- Docker 侧接口不需要变更
- 输出格式保持合规

## 开放风险

- 本地 `data/test.csv` 仍可能奖励某种在 walk-forward 中不稳定的模式
- 第三个模型可能只增加噪声，没有增加多样性
- 验证窗口长度可能仍不足以完全区分模型优劣
- 回归风格分数在集成前可能需要进一步裁剪或校准

这些风险在本阶段可以接受，因为设计中已经包含明确回退机制，并且保留了当前双排序模型方案作为安全基线。

## 实现边界

实现时应尽量保持改动小而清晰：

- 优先扩展现有训练工具，而不是重写主流程
- 特征生成继续在所有模型之间共享
- 推理接口继续以元数据驱动
- 新模型和集成策略尽量封装为边界清楚的辅助函数

## 最终设计包

摘要：在现有 XGB + LGB 方案基础上，通过更稳健的时序验证、验证驱动的多模型集成，以及 1 个离线友好的回归辅助模型，继续把本地分数向 `0.10+` 推进。

选定方案：采用推荐的多模型路线，先补 walk-forward 验证，再做可配置集成策略，并新增 1 个回归风格辅助模型，因为这条路在提分空间、可复现性和实际落地之间最平衡。

开放风险：主要风险是本地 score 过拟合、第三模型多样性不足，以及 fold 判别力有限，但这些风险都通过回退逻辑和保留现有双模型基线来控制。
